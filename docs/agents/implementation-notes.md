# Implementation notes for agents

Conventions established while implementing `.scratch/wallet-wagering-service/`. Read before changing code; update when you add a convention.

## Environment (Windows host)

- Use Git Bash. No gcc on the host: `go test -race` only via `scripts/test-race.sh [-tags=integration] ./...` (Docker, joins `wallet_default`).
- Host port 8081 is taken by another process: run compose with `KEYCLOAK_PORT=8082` and host tests with `TEST_KEYCLOAK_URL=http://localhost:8082` (issuer follows `KEYCLOAK_PORT`). The race script also needs it: `KEYCLOAK_PORT=8082 scripts/test-race.sh -tags=integration ./...` (otherwise every token is rejected with 401).
- Test infra: `KEYCLOAK_PORT=8082 docker compose up -d postgres keycloak ministack migrate sqs-init`. Tear down with `docker compose down -v` when done.
- Several agents may work at once. Only `git add` the files you changed; never `git add -A`.

## Layout

- `cmd/app` entry; `internal/bootstrap` Fx composition (`roleModules` map for `api`, `consumer`, `outbox`, `pending`).
- `internal/config` (`config.Load`, `cfg.OIDC`, `cfg.SQS`, `cfg.Roles`, `cfg.ShutdownTimeout`).
- `internal/domain/{money,wallet,ledger,wager,event}`: pure domain, stdlib + uuid only (a hygiene test enforces it).
- `internal/app`: use cases and ports (`UnitOfWork.Do(ctx, func(ctx, tx app.Tx) error)`, `Tx` exposes repositories), sentinels `ErrInvalidCommand`, `ErrWalletNotFound`, `ErrWalletAlreadyExists`, `ErrTransient`.
- `internal/postgres`: pgx repositories, `UnitOfWork` (`pgx.BeginFunc`), `classify()` maps retryable errors to `app.ErrTransient`, constraint names map to typed errors.
- `internal/httpapi`: routes via `httpapi.AsRoute(ctor)` in `httpapi.Module`; auth via `auth.Internal(h)` / `auth.Provider(h)`; `httpapi.PrincipalFrom(ctx)`; errors via `WriteError`, `WriteAppError` (extend its switch), strict `DecodeJSON`.
- `internal/health` readiness via `health.AsCheck`; `internal/observability` gives a per-app `*prometheus.Registry` (never the default registerer) and JSON `*slog.Logger`.
- `internal/sqs` SQS client module, input consumer (`ConsumerModule`) and events publisher; `internal/worker` for outbox and pending workers; `migrations/NNNNNN_desc.{up,down}.sql` (golang-migrate), embedded via `migrations.FS`.

## Persistence (schema from ticket 04 covers tickets 05-12)

- Migrations 000003-000006. Money columns: `<name>_minor BIGINT` + `currency CHAR(3)`. Enum-like columns are `text` with named CHECKs holding the domain's upper-case names.
- `wager_transactions` (mirrors `wager.Snapshot`, NULL = absent): `id, origin, kind, status, wallet_id` (no FK: WALLET_NOT_FOUND rejections are persisted), `player_id, amount_minor, currency, balance_after_minor, balance_after_currency` (the Wallet's currency; pair NULL together), `failure_code, provider_id, external_transaction_id, idempotency_key, payload_hash, round_id, game_id, reference_external_transaction_id, reference_transaction_id, compensated_bet_id, attempts, next_attempt_at, locked_until, created_at, updated_at`.
  - Constraint names to map in `classify`/repositories: `wager_transactions_provider_idempotency_key`, `wager_transactions_provider_external_transaction_id`, `wager_transactions_one_opening_per_wallet`, `wager_transactions_compensated_bet_key`, `wager_transactions_processed_reversal_reference_key` (all 23505); CHECKs `wager_transactions_origin_metadata`, `_failure_code_status`, `_processed_balance`, `_compensated_bet_reversal`, `_pending_reference`, `_reference_pair`, `_payload_hash_hex`.
  - Pending worker index: `wager_transactions_pending_reference_due (next_attempt_at) WHERE status='PENDING_REFERENCE'`. `next_attempt_at`/`locked_until` must stay NULL on Opening rows.
- `ledger_entries`: `id, wallet_id` (FK wallets), `transaction_id` (FK wager_transactions), `direction, amount_minor, currency, balance_before_minor, balance_after_minor, created_at`; `ledger_entries_wallet_transaction_key`, `ledger_entries_balance_arithmetic`, index `ledger_entries_wallet_created_id (wallet_id, created_at, id)`. Triggers raise P0001 on UPDATE/DELETE/TRUNCATE. `LedgerRepository.Append` returns the entry as stored (`created_at` may be pushed past the Wallet's last entry under clock skew); build events from the returned entry. Each event's `occurredAt` is its own row's stored time: `WalletBalanceChanged` = ledger `created_at`, `WagerTransaction*` = the transaction's `updated_at`; under clock skew the two may differ by the push. `ProcessWagerTransaction` and `ResumePendingReference` share `applyTo` + `persist` (`internal/app/apply.go`) for Apply and the ordered writes.
- `outbox_events`: `event_id` PK, `seq` identity (publish order per aggregate), `aggregate_id, event_type, version, correlation_id, payload` (text, exact `MarshalJSON` bytes, `CHECK payload IS JSON OBJECT`), `occurred_at, created_at DEFAULT now(), attempts, next_attempt_at DEFAULT now(), locked_until, published_at, last_error`; index `outbox_events_unpublished_due (next_attempt_at, seq) WHERE published_at IS NULL`.
- `inbox_messages`: PK `inbox_messages_consumer_message_key (consumer_name, message_id)`, `body_hash` (64 hex), `received_at, completed_at, transaction_id` (FK, nullable).
- Role `wallet_app` (password `wallet_app`, created idempotently by 000006): SELECT/INSERT/UPDATE on every table, only SELECT/INSERT on `ledger_entries`, no DELETE anywhere. A new table needs its own `GRANT` in its migration. The app connects as `wallet_app` (`DATABASE_URL`); compose's `migrate` uses `MIGRATE_DATABASE_URL` (owner `wallet`). The harness sets `infra.Config.DatabaseURL = infra.AppDatabaseURL`; `infra.DatabaseURL` is the owner, use `testsupport.OpenPool(t, infra.DatabaseURL)` for assertions (`testsupport.App.Pool` is the app role's pool).

## Application conventions

- Ports in `internal/app/app.go`; `app.Tx` exposes `Wallets()`, `Transactions()` (`Insert(*wager.Transaction)`), `Ledger()` (`Append(ledger.Entry)`, `List(walletID, after *app.LedgerPosition, limit)`), `Outbox()` (`Append(...event.Event)` stores `MarshalJSON` bytes). Pool-bound (non-transactional) `app.WalletRepository` and `app.LedgerRepository` are provided by `postgres.Module` for queries. Later tickets add methods (e.g. lookups by idempotency key, `FOR UPDATE` wallet reads) to these interfaces.
- Write order inside `UnitOfWork.Do`: wallet, wager transaction, ledger entry, outbox events.
- Correlation id: `app.WithCorrelationID(ctx, id)` / `app.CorrelationID(ctx)`; adapters set it (HTTP: `httpapi.WithCorrelation` wraps the whole mux, reads `X-Correlation-Id`, else UUIDv7, echoes it). Use cases copy it into `event.Meta` (OpenWallet generates one if missing). The JSON logger adds `correlationId` to any `...Context(ctx, ...)` record: always log with the request context.
- Wager operations (ticket 05): `app.ProcessWagerTransaction.Execute(ctx, app.WagerRequest{Command, Channel, CausationID, InTx}) (app.WagerResult{Transaction, Replay}, error)`, `internal/app/wagering.go`. HTTP builds `Command` with `wager.NewCommand` (Idempotency-Key header as the key) and passes `app.ChannelHTTP`; the SQS consumer (ticket 12) passes `app.ChannelSQS`, `CausationID = messageId`, `data.idempotencyKey` as key, and writes its Inbox Message in `InTx` (runs inside the same SQL transaction, after the writes, for new operations and replays; may run twice when the insert race retries; not called for the FAILED record).
  - Flow in one `UnitOfWork.Do`: `FindByIdempotencyKey` then `FindByExternalID` (match -> `wager.CheckReplay`: replay or 409 conflict); `Wallets().GetForUpdate` (not found -> nil wallet -> WALLET_NOT_FOUND persisted); lookup again (requests queued on the lock see the winner); Reference via `FindByExternalID(provider, refExtId)` + `IsCompensated(refID)` when `t.HasReference()`; `t.Apply`; `Wallets().Update(w, expectedVersion)` only with a ledger entry; `Transactions().Insert` (or `InsertPendingReference(t, policy.NextAttemptAt(0, now))` for PENDING_REFERENCE, which sets `next_attempt_at`); ledger; `event.ForTransaction`.
  - Insert race: the idempotency constraints map to `app.ErrDuplicateTransaction`; `Execute` retries once and the retry answers from the winner (replay or conflict). Proven by 50 parallel duplicates and 20 parallel duplicates on an unknown wallet (no row to lock).
  - Errors: wrapped `wager.ErrIdempotencyKeyConflict` / `wager.ErrExternalTransactionConflict` (409, mapped in `httpapi/wagering.go`), `app.ErrTransient` (503; `app.ErrConcurrencyConflict` wraps it and increments the conflict metric), `app.ErrInvalidCommand`. Any other error (overflow, CHECK violation, ...) is "permanent": `Execute` records the operation FAILED `PERMANENT_ERROR` in a separate transaction and returns it as a result (HTTP 500 with the transaction body; replays return it too). Context cancellation is never recorded.
  - HTTP status: 200 PROCESSED, 422 REJECTED, 202 PENDING_REFERENCE, 500 FAILED; replay keeps the original status with `idempotentReplay: true`. Check order in `POST /wagering/transactions`: auth, Idempotency-Key, strict body, body `providerId` vs token (403), `NewCommand` (400).
  - Queries: `app.GetWagerTransaction.ByID(ctx, providerID, id)` / `ByExternalID(ctx, providerID, extID)`, `app.ErrTransactionNotFound` for missing or other provider's (404). Pool-bound `app.TransactionRepository` is provided by `postgres.Module`.
  - Metrics (port `app.WagerMetrics`, implemented by `observability.WagerMetrics` on the per-app registry): `wallet_wager_transactions_total{kind,status}` (new outcomes only), `wallet_wager_duplicates_total{outcome=replay|idempotency_key_conflict|external_transaction_conflict}`, `wallet_concurrency_conflicts_total`, `wallet_wager_processing_seconds{channel,result}`. The use case logs `wager transaction handled` with `channel, providerId, externalTransactionId, walletId, kind, transactionId, status, idempotentReplay, failureCode` (never amounts or balances).
  - Tickets 06/07 (done) added no production code: idempotency and WIN/LOSS tests live in `internal/httpapi/replay_integration_test.go` and `win_loss_integration_test.go`. Helpers there: `operation(w, kind, amount)` (any kind, fresh external id), `winFor(w, amount, betBody)` (WIN referencing a BET of its Round), `requireReplayOf(t, got, original)`, `e.eventTypesOf(t, transactionID)` (Outbox Event types in seq order), `e.outboxCount`, `e.ledgerCount`. Restart pattern: `e.app.Stop(); cfg := e.infra.Config; cfg.OIDC.JWKSURL = e.forger.JWKSURL(); e.app = testsupport.StartApp(t, cfg)`. Ticket 10 reuses the same path (reversals already flow through `Apply`); Ticket 11 (done) re-runs `Apply` in `app.ResumePendingReference`, see "Pending References (ticket 11)".

- Ledger listing: `app.ListLedger` with `ListLedgerQuery{WalletID, Cursor, Limit}` (0 = 50, max 200); cursor = base64url(8-byte Unix micros + 16-byte id) via `app.EncodeLedgerCursor`/`DecodeLedgerCursor`.
## Domain API cheat sheet

- `wager.NewCommand(CommandInput)` (400 on error, `wager.ErrInvalidCommand`), `wager.PayloadHash`, `wager.CheckReplay(existing, cmd)`.
- `wager.NewExternal(cmd, now)`; `tx.Apply(wallet /*nil = not found*/, wager.Reference{Transaction, Compensated}, now) (*ledger.Entry, error)`: business rejections are recorded on tx (nil error); read `tx.Status()` after.
- `wager.Open(wallet, initial, now)` returns the PROCESSED Opening + credit entry (nil, nil for zero); `wallet.ApplyOpening` keeps version 1.
- `tx.RecordReferenceMiss(policy, now)` for the pending worker; `wager.DefaultPendingPolicy()`.
- `tx.Snapshot()` / `wager.Rehydrate(Snapshot)` map to persisted columns.
- `compensatedBetID` is set only on PROCESSED REFUND/ROLLBACK of a BET: index `UNIQUE (compensated_bet_id) WHERE compensated_bet_id IS NOT NULL`. Also `UNIQUE (reference_transaction_id) WHERE kind IN ('REFUND','ROLLBACK') AND status='PROCESSED'`.
- `event.ForTransaction(tx, entry, walletVersion, meta)` gives the Outbox Events for a transaction; `aggregateId` is always the walletId; `Event.MarshalJSON` is the snapshot payload.
- `wager.FailurePermanentError` (`PERMANENT_ERROR`) is the Failure Code for FAILED.

## Reconciliation (ticket 08)

- `POST /wallets/{walletId}/reconciliation` (internal client) runs `app.Reconcile`. Its port `app.ReconciliationReader` (`postgres.ReconciliationReader`) is separate from `app.Tx`: one `REPEATABLE READ READ ONLY` transaction reads the stored balance, `sum(credits) - sum(debits)` (numeric in SQL, error if outside int64) and the entry count. A divergence still answers 200, with `consistent:false`.
- Observability: `app.ReconciliationMetrics` (`observability.ReconciliationMetrics`) exposes `wallet_reconciliations_total{result="consistent"|"divergent"}` and `wallet_reconciliation_divergences_total`; a divergence logs ERROR `reconciliation divergence` with `walletId`, `storedBalance`, `calculatedBalance`, `difference`, `currency`, `checkedEntries`, `correlationId`.
- Test helpers (`internal/httpapi/reconciliation_helpers_integration_test.go`): `e.reconcile(t, walletID)` returns the report (fails unless 200); `e.requireConsistent(t, walletID)` fails unless consistent. ## Workers (ticket 09; reused by ticket 11)

- Lifecycle: `worker.NewLoop(name, pollInterval, cycle, log)`; register with `lc.Append(loop.Hook())` from an `fx.Invoke` in the role module (e.g. `worker.OutboxModule`, wired in `bootstrap.roleModules`). The loop depends on the pool and SQS client, so Fx stops it before closing them.
- `worker.Cycle func(soft, hard context.Context) (busy bool)`: `soft` is canceled on OnStop (claim nothing new, release unstarted work); `hard` is canceled only when `SHUTDOWN_TIMEOUT` expires (run started SQL/SQS work under it). Return true to run again at once, false to wait the poll interval. `Loop.Stop` always waits for the goroutine (goleak-clean).
- Claim/lease: one statement, `WITH candidates AS (SELECT ... ORDER BY seq LIMIT n FOR UPDATE SKIP LOCKED) UPDATE ... SET locked_until = now() + lease ... RETURNING`. The returned `locked_until` is the lease token (same for the whole batch; strictly greater on every takeover, since a row is reclaimed only after it expired). Every later write is guarded by `WHERE locked_until = $token AND published_at IS NULL`, so no owner column or migration is needed. See `postgres.OutboxStore` (`Claim`, `MarkPublished`, `MarkFailed`, `Release`, `OldestUnpublishedAge`).
- Outbox ordering: a candidate is leased only if every older unpublished event of its aggregate is in the same claim; the batch is sent in seq order and a failed send releases the aggregate's later events. Per-Wallet FIFO order holds across publishers, with head-of-line blocking per Wallet only. A publisher stops starting sends once 4/5 of the lease elapsed and releases the rest.
- Retries: `worker.Backoff{Base, Max}.Delay(attempt)` (attempt 1 = first retry), exponential, capped, jitter in `[d/2, d]`. Outbox uses `OUTBOX_RETRY_BASE`/`OUTBOX_RETRY_MAX` (`cfg.Outbox`, parsed in `internal/config/outbox.go` with the `positiveDuration` helper).
- Crashpoints: `crashpoint.Hit(crashpoint.OutboxBeforePublish)` / `OutboxAfterPublish`; see "Fault injection (ticket 14)".
- Tests: `internal/worker/outbox_integration_test.go` seeds `outbox_events` as the owner, starts apps with `cfg.Roles = []config.Role{config.RoleOutbox}` and short `cfg.Outbox` intervals, and wraps `worker.Publisher` with `fx.Decorate` to count or block sends (FIFO dedup would hide duplicate sends inside 5 minutes, so duplicates are counted at the publisher). Deleting and recreating the per-test events queue in MiniStack returns the same URL (used to simulate SQS unavailable).
- Metrics: `wallet_outbox_lag_seconds`, `wallet_outbox_published_total`, `wallet_outbox_publish_failures_total`, `wallet_outbox_retries_total`.

## Reversals (ticket 10)

- No separate flow: REFUND/ROLLBACK go through `ProcessWagerTransaction`; `wager.ResolveReference` holds the rules (kind compatibility, Reference status, player/Wallet/currency/Round, amount, Compensated). The Reference is looked up by `(token providerId, referenceExternalTransactionId)` under the Wallet lock, so another provider's BET is an absent Reference (202 `PENDING_REFERENCE`, nothing moves).
- `IsCompensated(refID)`: a row with `compensated_bet_id = refID` or a PROCESSED REFUND/ROLLBACK with `reference_transaction_id = refID`. A ROLLBACK of a REFUND sets no `compensated_bet_id`; the REFUND keeps the BET's slot (ADR-0002).
- Backstop: violations of `wager_transactions_compensated_bet_key` / `_processed_reversal_reference_key` on `Insert` map to `app.ErrCompensationConflict` (wraps `app.ErrDuplicateTransaction`); `Execute` retries once and answers `REFERENCE_ALREADY_COMPENSATED`, never FAILED.
- Test helpers (`internal/httpapi/reversals_integration_test.go`): `reversalOf(ref, kind)`, `rvWin(w, amount)`, `rvLoss(w)`, `withMoney(b, amount, currency)`, `e.expectRejected(t, b, code, balance)`, `e.expectReplay(t, b, status, original)`, `e.reversalRow(t, id)`, `e.ledgerOf(t, txID)`, `e.eventTypesOf(t, walletID, txID)` with `expectEvents`, `expectUniqueViolation(t, err, constraints...)`, `e.openWalletUSD(t, player)`.

## Pending References (ticket 11)

- Config `cfg.Pending` (`internal/config/pending.go`): `PENDING_MAX_ATTEMPTS` (8, 1-1000), `PENDING_RETRY_BASE`/`PENDING_RETRY_MAX` (2s/2m), `PENDING_POLL_INTERVAL` (1s), `PENDING_BATCH_SIZE` (20), `PENDING_LEASE_DURATION` (30s); helper `boundedInt`. `cfg.Pending.Policy()` builds `wager.PendingPolicy`; `bootstrap.Options` provides it to the whole graph, and `app.NewProcessWagerTransaction(uow, policy, metrics, log)` takes it (every role schedules the first retry when it parks an operation).
- Role `pending` = `worker.PendingModule` (`internal/worker/pending.go`): provides `postgres.NewPendingStore`, `observability.NewPendingMetrics` (as the `app.PendingMetrics` port), `app.NewResumePendingReference`, `NewPendingWorker`. The cycle: `PendingStore.Claim(soft, batch, lease)` (same lease-token pattern as the outbox: `locked_until` returned as token, `ORDER BY next_attempt_at`, `FOR UPDATE SKIP LOCKED`), `crashpoint.Hit(crashpoint.PendingAfterClaim)`, then one `ResumePendingReference.Execute(hard, item)` per row; on soft cancel or after 4/5 of the lease it `Release`s the unstarted rows. A failed retry keeps its lease (retried after it expires). Backlog gauge via `PendingStore.Backlog`.
- `app.ResumePendingReference.Execute(ctx, app.PendingItem{TransactionID, WalletID, Lease}) (app.PendingOutcome, error)` (`internal/app/pending.go`), one `UnitOfWork.Do`: `Wallets().GetForUpdate`, `Pending().GetLeased(id, token)` (FOR UPDATE; `app.ErrLeaseLost` when not PENDING_REFERENCE under that lease -> outcome `skipped`), `lookupReference`, `Apply`; still waiting -> `RecordReferenceMiss` -> `Pending().Save(t, &next, token)` (no event) or expired (REJECTED `REFERENCE_NOT_FOUND`); resolved -> versioned Wallet update, `Pending().Save(t, nil, token)`, ledger, `event.ForTransaction`. `Save` is an UPDATE guarded by id + `status='PENDING_REFERENCE'` + `locked_until=token` that clears the lease (and `next_attempt_at` once resolved). Compensation index violation -> `app.ErrCompensationConflict`, retried once in place (answers `REFERENCE_ALREADY_COMPENSATED`). Any other permanent error -> separate transaction records FAILED `PERMANENT_ERROR` (outcome `failed`).
- Port: `app.Tx.Pending() app.PendingReferenceRepository` (`postgres.PendingReferenceRepository`, `internal/postgres/pending_claim.go`).
- No nudge: when a Reference arrives, dependents wait for their scheduled retry (at most `PENDING_RETRY_MAX`). Correlation id of a worker retry is fresh (the original is not stored on the row); events carry no causation id.
- Replay of a pending operation answers 202 with the current row; after resolution it answers the final persisted result (200/422 with `idempotentReplay: true`).
- Metrics: `wallet_pending_reference_retries_total`, `wallet_pending_reference_resolutions_total{outcome=processed|rejected|expired|failed}`, `wallet_pending_reference_backlog`.
- Tests: `internal/httpapi/pending_integration_test.go`. `newPendingEnv(t, pendingSettings())` starts roles api+pending with millisecond retries; `pendingConfig(e, p, roles...)`, `e.restartWith(t, cfg)`, `e.pendingRow(t, id)`, `e.awaitResolution(t, id)`, `e.sendPending(t, body)`, `e.metricValueOr(t, series, def)`, `slowUnitOfWork` (decorate `app.UnitOfWork` to widen shutdown windows). A second instance on the same DB: `testsupport.StartApp(t, pendingConfig(e, p, config.RolePending))`. To simulate a live or abandoned lease, set `locked_until` as the owner.

## SQS consumer (ticket 12)

- Role `consumer` -> `sqs.ConsumerModule` (`internal/sqs/consumer.go`): provides `app.ConsumeWagerMessage` (`internal/app/inbox.go`) and `*sqs.Consumer` with its own `fx.Hook`. It does not use `worker.Loop` because `internal/worker` imports `internal/sqs` (import cycle); `Consumer.retryDelay` repeats the `worker.Backoff` formula, rounded up to whole seconds.
- Config `cfg.Consumer` (`internal/config/consumer.go`): `CONSUMER_NAME` (inbox `consumer_name`, default `wager-transactions`), `CONSUMER_CONCURRENCY` (10), `CONSUMER_WAIT_TIME` (20s, whole seconds 0-20), `CONSUMER_VISIBILITY_TIMEOUT` (30s, whole seconds; heartbeat every 1/3), `CONSUMER_RETRY_BASE`/`_MAX` (1s/2m). `SQS_DLQ_QUEUE_URL` -> `cfg.SQS.DLQQueueURL`, required only with the consumer role; the harness sets it (`infra.DLQQueueURL`) and the SQS readiness check includes it when set.
- Envelope (`sqs.ParseEnvelope`, `internal/sqs/envelope.go`): `{messageId, type:"WagerTransactionRequested", version?:1, occurredAt (RFC 3339), correlationId?, data:{providerId, externalTransactionId, idempotencyKey, playerId, walletId, roundId, gameId, kind, money, referenceExternalTransactionId?}}`, strict at both levels. `data` -> `wager.CommandInput` -> `wager.NewCommand`, so the rules and Payload Hash equal HTTP's. Errors are `*sqs.PermanentError{Reason}`: `malformed_json`, `unknown_envelope`, `invalid_envelope`, `invalid_command`, `opening_kind`; the consumer adds `body_hash_mismatch`, `idempotency_key_conflict`, `external_transaction_conflict` (409-equivalents are permanent: resending the same message never resolves them).
- Inbox: `app.Tx.Inbox()` (`app.InboxRepository`: `Find`, `Insert`; `postgres.InboxRepository`). Key = envelope `messageId`; `body_hash` = SHA-256 of the raw body (`sqs.BodyHash`). `ConsumeWagerMessage.Execute(ctx, app.InboxRequest{ConsumerName, MessageID, BodyHash, ReceivedAt, Command})`: pre-check in its own read tx (same hash -> `InboxResult{Duplicate: true, Wager: {Transaction: the recorded row}}`, other hash -> `app.ErrInboxHashMismatch`), then `ProcessWagerTransaction.Execute` with `ChannelSQS`, `CausationID = messageId` and `InTx` inserting the Inbox Message (`completed_at` set, `transaction_id` = new or replayed row; PENDING_REFERENCE included). The insert race on the PK returns `app.ErrInboxMessageExists` (wraps `ErrTransient`, so no FAILED record) and is resolved by re-reading the inbox. A new FAILED record gets its Inbox Message in a separate tx.
- Settling: success or duplicate -> `crashpoint.ConsumerAfterCommit` -> `DeleteMessage`; a FAILED operation (new, Replay or inbox duplicate: `app.InboxResult.Wager` carries the recorded operation on duplicates too) -> DLQ `permanent_error`; permanent -> `SendMessage` to the DLQ (same body and group, dedup id = SQS MessageId, attributes `dlqReason`, `dlqDetail`, `dlqSourceMessageId`) then delete (a failed DLQ send is retried like a transient error); transient or unknown -> `ChangeMessageVisibility(backoff(ApproximateReceiveCount))`, and SQS redrives after 5 receives (no `dlqReason`). Settling calls use `context.WithoutCancel` plus a 10s timeout.
- Concurrency: slots = `CONSUMER_CONCURRENCY`; a batch (at most 10 and the free slots) is split by `MessageGroupId`, each group handled sequentially in its own goroutine; a message not completed releases the rest of its group (visibility 0). Shutdown: `Stop` cancels polling (soft), waits until `deadline - min(remaining/5, 3s)`, then cancels in-flight work (hard), which rolls back and releases visibility 0; it returns nil in that case, so fxtest `RequireStop` passes.
- Metrics (a FAILED operation counts as `handled{result="dead_lettered"}` plus `dlq{reason="permanent_error"}` once per message sent, so a redelivered FAILED duplicate also bumps `wallet_inbox_duplicates_total` and the DLQ counter again): `wallet_sqs_messages_received_total`, `wallet_sqs_messages_handled_total{result}`, `wallet_sqs_dlq_messages_total{reason}`, `wallet_inbox_duplicates_total`, `wallet_sqs_retries_total`, `wallet_sqs_visibility_extensions_total`. Logs `sqs message handled`, `sqs message sent to the dlq`, `sqs message will be retried`, `sqs message released` carry `sqsMessageId`, `messageId`, `providerId`, `walletId`, `externalTransactionId`, `transactionId`, `correlationId`.
- Tests (`internal/sqs/consumer_*_integration_test.go`): `newEnv(t, tweak)` starts api+consumer (wait 1s, retry 1s/1s); `op(w, kind, amount)` + `envelopeOf(op)` build messages; `e.sendEnvelope` / `e.send(t, group, body)` send with a fresh `MessageDeduplicationId` (this simulates a redelivery after the FIFO window); `e.waitRow`, `e.inbox`, `e.waitQueueEmpty`, `e.dlqMessages(t, n, within)` (reads and deletes, since an in-flight DLQ message blocks its group); `e.lockWallet` + `e.waitBlocked` + `e.terminateBlocked` hold or kill work in progress; `metric(t, app, series)`.
- MiniStack quirks: a second `SendMessage` with an already used `MessageDeduplicationId` and a different body fails the SDK MD5 check (the emulator answers with the first message's MD5), so send with a fresh dedup id. Redrive, per-receive `VisibilityTimeout`, FIFO group blocking and `ApproximateReceiveCount` behave like SQS.
- e2e (ticket 13): send `WagerTransactionRequested` bodies to `SQS_INPUT_QUEUE_URL` with `MessageGroupId = walletId` and `MessageDeduplicationId = messageId`; observe rows, `inbox_messages`, the DLQ and `/metrics`.

## e2e harness (ticket 13; reused by ticket 14)

- Package `test/e2e` (`package e2e_test`, every file `//go:build e2e`). `TestMain` builds `./cmd/app` once into a temp dir; it adds `-race` when the test binary is race-enabled (`raceEnabled`, from `flags_race_test.go` / `flags_norace_test.go`) and `-tags faultinject` under that tag (`faultinjectEnabled`, `flags_faultinject_test.go`). Ticket 14 files use `//go:build e2e && faultinject`.
- Commands: host `TEST_KEYCLOAK_URL=http://localhost:8082 go test -tags=e2e -timeout 10m ./test/e2e/...`; race `KEYCLOAK_PORT=8082 scripts/test-race.sh -tags=e2e -timeout 10m ./test/e2e/...` (no script change was needed: the binary is built and run inside the container, and the instances reach postgres/keycloak/ministack by compose name through the same `TEST_*` variables). About 50s either way.
- `NewCluster(t, overrides)` = `testsupport.NewInfra` + owner pool `c.DB` + 3 ready instances. Env = `os.Environ()` + infra endpoints (incl. `SQS_DLQ_QUEUE_URL`) + `baseEnv` (all roles, 100ms outbox/pending polls, pending retries 100ms..500ms, `PENDING_MAX_ATTEMPTS=1000`, `PENDING_LEASE_DURATION=3s`, `OUTBOX_LEASE_DURATION=5s`, `CONSUMER_WAIT_TIME=1s`, `LOG_LEVEL=info`) + `overrides` + a free `HTTP_ADDR`. `NewStoppedCluster` starts none.
- Instances: `c.Start(t, extra)` (waits for `/health/ready`), `c.Launch(t, extra)` (no wait; use for an instance that may crash early), `c.StartAll(t, n, extra)`, `c.StopAll(t)`, `c.Running()`, `c.Next()` (round-robin over running ones). `inst.Stop(t)` = SIGTERM + wait (exit 0 required) on unix, `Kill` on Windows (`gracefulStop`); `inst.Kill(t)`; `inst.WaitExit(t, timeout) int` returns the exit code, so a crashpoint is `c.Launch(t, map[string]string{"CRASH_AT": "outbox.before_publish"})` then `if code := inst.WaitExit(t, 30*time.Second); code != 137 {...}`; `inst.Exited()`, `inst.ExitCode()`, `inst.Logs()`, `inst.LogPath`. Every instance is stopped on cleanup; its log tail is printed when the test failed, and `WARNING: DATA RACE` in any log fails the test.
- Requests: `c.Send(t, inst, body, status)` (provider-a token, key `providerId:externalTransactionId`), `c.PostWager(inst, token, body)` (no `t`, goroutine-safe; fetch the token first), `c.sendAll(t, bodies, parallel)` (round-robin, concurrent), `c.OpenWallet(t, inst, "100.00")`, `c.SendSQS(body, messageID)` (envelope with idempotencyKey = the same key, group = walletId, dedup = messageID). Bodies: `bet(w, amount)` (random round), `reversalOf(ref, kind)`.
- Checks: `c.RequireConsistent(t, walletIDs...)` (endpoint + SQL: stored == credits - debits == last balance_after, one entry per transaction), `c.RequireEventsDelivered(t)` (waits until every outbox row is published, drains the events queue with 4 receivers, checks each eventId once, group = aggregateId, dedup = eventId, per-Wallet seq order; returns counts by eventType), `c.DrainEvents(t, n)`, `c.AwaitStatus(t, extID, status, failureCode, timeout)`, `c.Balance`, `c.Debits`, `c.Count`, `Eventually(t, timeout, what, cond)`.
- Windows: `os.Process.Signal` cannot deliver SIGTERM/interrupt to another process, so graceful shutdown is only exercised in the Linux race container. A killed process reports exit code 1 on Windows and -1 (signal) on unix; `os.Exit(137)` reports 137 on both.

## Fault injection (ticket 14)

- `internal/crashpoint`: `hit.go` (`//go:build !faultinject`: `const Enabled = false`, no-op `Hit`) and `hit_faultinject.go` (`//go:build faultinject`: `Enabled = true`, `ExitCode = 137`, `Known` names). `CRASH_AT` is parsed once at package init (`armed`, comma-separated, unknown names logged as a warning and ignored); `Hit(name)` logs `crashpoint hit, exiting` (JSON on stderr, field `crashpoint`) and calls `os.Exit(137)` (no deferred calls, no Fx stop). A new crashpoint needs its constant in `crashpoint.go` and in `Known`.
- Tests: `hit_test.go` (`!faultinject`) asserts `Enabled == false` and builds `cmd/app` with and without `-tags faultinject`, checking `go tool nm` for `internal/crashpoint.armed` (absent without the tag, present with it; skipped with `-short`, about 10s). `hit_faultinject_test.go` tests `arm` and re-runs the test binary with `CRASH_AT` to assert exit 137.
- e2e (`test/e2e/faultinject_test.go`, `//go:build e2e && faultinject`): each scenario uses `NewStoppedCluster`, an api-only instance (`c.Start(t, {"APP_ROLES": "api"})`) that creates the work, then `c.crashAt(t, role, point, trigger)` (launches one instance with only that role plus `CRASH_AT`, runs `trigger`, requires exit 137 and the crash log line), then `c.StartAll(t, 2, nil)` healthy instances. `c.metricSum(t, series, instances)` sums an unlabeled series over `/metrics`. Overrides: `CONSUMER_VISIBILITY_TIMEOUT=2s` (consumer), `OUTBOX_LEASE_DURATION=2s` (outbox); pending uses the base 3s lease.
- MiniStack honours FIFO deduplication on a same-body resend with the same `MessageDeduplicationId`, so after `outbox.after_publish` the strict `RequireEventsDelivered` (each eventId exactly once) holds; the resend itself is proven by `wallet_outbox_published_total` on the survivors equalling the outbox row count (the crashed instance never increments it).
- Commands: host `TEST_KEYCLOAK_URL=http://localhost:8082 go test -tags=e2e,faultinject -timeout 10m ./test/e2e/...` (about 60s, whole suite); race `KEYCLOAK_PORT=8082 scripts/test-race.sh -tags=e2e,faultinject -timeout 10m ./test/e2e/...` (about 80s).
